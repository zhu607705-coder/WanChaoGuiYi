# Dynasty Cycle Acceptance Scenarios

## 目的

本文件定义全量 MVP 收口的第一条长线验收：证明一个强盛王朝会在普通扩张和治理中进入过热、危机、崩盘或续命路径。

它不是新系统设计，而是把已经存在的 MVP 系统串成可验证闭环：

- 扩张后的治理拖累
- 财政和粮食压力
- 军队和补给负担
- 土地兼并和民变风险
- 合法性和继承压力
- 模拟观战与玩家战役指挥接管
- UI 原因、行动和后果解释

## 总体验收线

玩家开一局后可以：

1. 自动模拟若干回合，观察帝皇势力扩张、过热和危机。
2. 在关键节点接管一个王朝。
3. 通过战役指挥、治理、财政和继承处理尝试续命。
4. 看到 UI 解释危机原因、可做行动、代价收益和行动后变化。

## Headless 长线场景

### 场景 A：强盛王朝扩张后过热

目标：证明扩张不是纯收益。

初始条件：

- 玩家势力拥有稳定核心区、较高金钱和粮食、较低民变。
- 连续占领 2 到 3 个相邻地区。
- 新占地区进入 `Occupied` / 新占治理链，贡献率低于核心区。

期望变化：

- 地区数上升。
- 合法性因占领或治理压力下降。
- 新占地区税粮贡献低于完整控制地区。
- 军队补给或占后安抚消耗粮食。
- 至少一个压力指标上升：`successionRisk`、`rebellionRisk`、`annexationPressure`、`localPower` 或等价运行态字段。

最低断言：

- 扩张后总控制区增加，但单位地区净收益下降或治理成本上升。
- 报告必须包含 `keyDelta`，解释“为什么扩张带来压力”。

### 场景 B：财政军队土地挤压

目标：证明玩家不能同时无限征兵、扩张、重税和稳定地方。

初始条件：

- 玩家势力有一支主力军、至少一个高地方势力地区、一个可征税/征兵核心区。
- 连续执行急征税、征兵或前线整备。

期望变化：

- 金钱或粮食改善一项，但民变、合法性、人口、兵源或地方压力恶化。
- 玩家能看到至少一个政策/行动的代价解释。

最低断言：

- 资源收益和风险代价同时出现。
- 不能只检查数值变化，必须检查解释文本或 report reason。

### 场景 C：继承压力触发王朝危机

目标：证明强盛王朝可能因继承不稳进入危机。

初始条件：

- 玩家势力已扩张到多个地区。
- 帝皇或势力存在低继承控制、高扩张压力或高朝局压力。

期望变化：

- `successionRisk` 或等价继承压力随扩张/时间增长。
- 达到阈值后触发继承危机事件、合法性损失、派系压力、叛乱风险或分裂风险。

最低断言：

- 继承压力不是孤立字段，必须影响合法性、地方稳定或胜利/失败路径。
- UI 或 headless report 必须解释危机来源。

### 场景 D：玩家接管续命

目标：证明玩家下场接管能改变危机走向。

初始条件：

- 使用场景 A/B/C 形成的过热王朝。
- 玩家接管后可执行治理、财政、继承或战役指挥动作。

期望变化：

- 至少一个危机指标被缓解。
- 至少一个资源或战略机会被牺牲。
- 战役指挥动作仍停留在路线、补给、进退和自动结算层，不进入战术战斗。

最低断言：

- 接管前后存在清晰对比。
- 结果必须能说明“玩家做了什么，所以局势如何改变”。

## Web/Playwright 验收补充

Headless 负责因果，Web 负责玩家理解。

需要新增或扩展的 UI 验收：

1. 自动模拟后 outliner 展示至少一个王朝压力摘要。
2. 地区或势力面板展示最大风险、原因、可做行动和预计后果。
3. 玩家执行一个治理或战役指挥动作后，操作日志显示行动后变化。
4. 存档导出/导入后保留关键压力状态和战役上下文。

## 禁止事项

- 不用战术战斗替代战役指挥验收。
- 不把继承、人才、科技、建筑等现有 MVP 片段降级成“以后再说”。
- 不用单一数值断言冒充玩家可理解的危机解释。
- 不新增与王朝周期无关的系统来掩盖收口缺口。

## 第一批实现建议

1. 在 headless 测试中增加 `DynastyCyclePressureAcceptanceTests`。
2. 先从场景 A 和 B 入手，因为它们复用现有占领、税压、征兵、补给和治理规则。
3. 场景 C 需要先盘点继承压力当前实际接入点，再补最小危机场景。
4. 场景 D 依赖 A/B/C 的危机状态，放在第二批。
